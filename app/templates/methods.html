METHODS / BINARY REPAIR

方法与工具

二进制修复不是「一个工具给出答案」，而是一条证据链：定位、静态恢复、符号探索、 动态确认、差分验证与回归输入。每一环都只能回答一部分问题。

查看本机接入状态

修复链

  1. 01
    复现与定位

    先固定可重复的崩溃/错误输入，记下版本、环境与调用路径；没有复现就没有「修好了」。

  2. 02
    静态恢复

    用 Ghidra/Rizin/objdump 恢复函数边界与伪代码，标出缺陷区间与相邻控制流。

  3. 03
    符号探索

    angr/Triton 求「哪些输入能到达危险点」，把候选输入变成可检查的约束。

  4. 04
    动态确认

    Frida/GDB/QEMU 在真实或模拟环境里观察寄存器、内存和 API，确认路径确实发生。

  5. 05
    差分验证

    比较修复前后的二进制与行为：目标缺陷消失，其他行为没有意外变化。

  6. 06
    回归与模糊

    AFL++/syzkaller 找相邻路径与回归；通过不等于安全，只是没有发现新的反例。

工具矩阵

STATIC

Ghidra · Rizin · objdump

无头反编译、函数/符号恢复与静态证据。Route B 的 objdump/readelf 输出用于基线自检；它证明的是「观察到的字节与指令」，不是「行为正确」。

在本工作台：连接器 ghidra、rizin、binutils 会探测本机是否具备条件。

Ghidra ↗ Rizin ↗ binutils ↗
SYMBOLIC

angr · Triton

把「如何到达危险点」转成路径约束。适合边界清晰的小函数；路径爆炸、外部调用与并发会让模型失真。

在本工作台：angr、triton 作为 Python 模块接入；未安装时连接器显示「未检测到」。

angr ↗ Triton ↗
DYNAMIC

Frida · GDB · QEMU

运行时插桩、崩溃现场与跨架构模拟。动态证据最接近真实执行，但依赖环境、输入与观察点选择。

在本工作台：frida、gdb、qemu 探测 PATH；工具就绪只代表可以发起请求。

Frida ↗ GDB ↗ QEMU ↗
DIFF

Diaphora · BinDiff

把修复前后的二进制函数对齐，定位变化区间；差异本身不是正确性证明，但能暴露意外改动。

在本工作台：差分结果进入证据页，和契约、验收义务分开展示。

Diaphora ↗ BinDiff ↗
FUZZ

AFL++ · syzkaller

覆盖引导的输入生成，用于发现回归与相邻路径；内核/系统调用面适合 syzkaller，用户态目标适合 AFL++。

在本工作台：模糊测试是候选证据来源，不能替代人工契约与验收结论。

AFL++ ↗ syzkaller ↗
CONTAINMENT

Docker · 隔离运行

不可信样本应在容器或专用虚拟机里运行，限制网络、挂载与权限；工具就绪不等于沙箱配置正确。

在本工作台：连接器 docker 只探测 CLI，不自动启动容器。

Docker ↗

验证要回答的四个问题

1. 缺陷真的复现了吗？

输入、版本、环境、崩溃信号必须可重复；不可复现的修复只是猜测。

2. 补丁只改了目标行为吗？

差分、回归用例与相邻路径检查；意外改动和未覆盖路径都要显式记录。

3. 证据来自哪一层？

静态、符号、动态、模糊各自有边界；不能把「模型说可以」当成运行结果。

4. 谁给出结论？

验收引擎按契约判定；助手、工具和页面都不自行宣布「已修复」。
