# Honest non-goals and residual gaps (2026-11-14)

This page maps every audit `non_goal` record to a declaration in
`docs/status/claims.json` (`non_goals`) and to the enforcement that keeps it from
being reported as a success. The source of truth is the measured audit:
`artifacts/capability-gap-audit-2026-11-14/coverage-matrix.json`
(`gap-report.md` is the human view). Rows are re-measured by
`scripts/audit_capability_coverage.py`; this page is the mapping/registry, not a
second status list.

Enforcement vocabulary (what the product does for that class, never a success):

- `unsupported` - the input/strategy returns `unsupported`; no candidate bytes.
- `analysis_only` - analysed, no patchable sink for the declared target; no candidate.
- `not_run` / `no verified` - runtime evidence is missing; the gate stays
  `not_run`/`inconclusive`; `verified_patch` and download are never produced.
- `no download` - even a static-only opt-in candidate is explicitly unverified.

## 3. What the coverage gate enforces

`scripts/verify_coverage_gate.py` (default `--static-only`, CI/PR mode) asserts:

1. no `GM-detector-error::*` audit rows (the audit itself must be healthy);
2. no high-severity open gaps;
3. open gap ids are a subset of the explicit `ALLOWED_OPEN` residual set
   documented in the script header (currently empty, no silent acceptance);
4. every measured `non_goal` gap id is mapped in this page or in
   `docs/status/claims.json` `non_goals`; every claims non-goal id is measured
   as a static `non_goal` or `dynamic_unverified` audit row;
5. `docs/status/claims.json` `non_goals` entries are structurally valid:
   `id`/`category`/`enforcement`/`claim`/`owner`/`review_by` (ISO date,
   <= 2027-05-14)/`productization_criteria`/`fallback`, all 11 present;
6. probe-dependent gaps are honest in static mode: they are
   `dynamic_unverified` (neither closed/mitigated nor open) and counted; the
   capability universe has `unknown == 0`, every non_goal/unavailable cell has
   an explicit reason, non_goal cells referencing claims ids are mapped, the
   status counts agree with the cells, and every declared dimension value
   appears in at least one cell;
7. the meta-audit passes (detector recall >= 0.8, precision = 1.0, injected
   defects detected, fabricated gaps rejected) - exposed in static mode,
   required in `--local`;
8. the acceptance-invariant engine accepts the committed acceptance evidence
   (`verified`/`rejected`/`not_run`/target-scope/rewrite/manifest-legacy/
   download invariants) - exposed in static mode, required in `--local`.

`--local` additionally runs the bounded dynamic audit probes and requires the
real-guest acceptance capture `artifacts/coverage-closure-2026-11-14/
acceptance.json` to exist with `passed: true`, `dynamic_unverified_count == 0`,
the claims ids to equal the measured `non_goal` ids exactly, the meta-audit to
pass and the invariant engine to pass over the committed packets.

Status is measured, never hard-coded: a detector closes a row only from live
imports/probes, and this page/claims list is regenerated from the measured
audit ids by the audit owner.
