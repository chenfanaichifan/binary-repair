# Honest non-goals and residual gaps (2026-11-14)

This page maps every audit `non_goal` record to a declaration in
`docs/status/claims.json` (`non_goals`) and to the enforcement that keeps it from
being reported as a success. The source of truth is the measured audit:
`artifacts/capability-gap-audit-2026-11-14/coverage-matrix.json`
(`gap-report.md` is the human view). Rows are re-measured by
`scripts/audit_capability_coverage.py`; this page is the mapping/registry, not a
second status list.

Enforcement vocabulary (what the product does for that class, never a success):

- `unsupported` - the input/strategy returns `unsupported`; no candidate bytes.
- `analysis_only` - analysed, no patchable sink for the declared target; no candidate.
- `not_run` / `no verified` - runtime evidence is missing; the gate stays
  `not_run`/`inconclusive`; `verified_patch` and download are never produced.
- `no download` - even a static-only opt-in candidate is explicitly unverified.

## 3. What the coverage gate enforces

`scripts/verify_coverage_gate.py` (default `--static-only`, CI) asserts:

1. no `GM-detector-error::*` audit rows (the audit itself must be healthy);
2. no high-severity open gaps;
3. open gap ids are a subset of the explicit `ALLOWED_OPEN` residual set
   documented in the script header (kept explicit, no silent acceptance);
4. every measured `non_goal` gap id is mapped in this page or in
   `docs/status/claims.json` `non_goals`, and the claims list is structurally
   valid (`id`/`category`/`enforcement`/`claim`);
5. `docs/status/claims.json` parses.

`--local` additionally runs the bounded dynamic audit probes and requires
`artifacts/coverage-closure-2026-11-14/acceptance.json` to exist with
`passed: true` (the real-guest acceptance capture).

Status is measured, never hard-coded: a detector closes a row only from live
imports/probes, and this page/claims list is regenerated from the measured
audit ids by the audit owner.
