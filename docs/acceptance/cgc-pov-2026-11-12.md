# CGC POV 探索性重放（2026-11-12）

## 结论

- 5 对 CGC challenge 已交叉编译为 **Linux x86-64 ELF**（静态、musl），
  并构建了 7 个 POV；产物见 `datasets/cgc-linux-build/`。
- 在 Ubuntu 24.04 arm64（Lima `vz`）+ `qemu-x86_64-static 8.2.2` 下重放：
  - **2/7 得到干净的 crash 差分**：`Palindrome`、`basic_messaging`
    的 vulnerable 均 SIGSEGV，patched 均 exit 0；各重复 3 次一致。
  - `Board_Game` 只有行为差异（vulnerable exit 0，patched exit 1），
    不是 crash PoV。
  - `3D_Image_Toolkit`、`CGC_Hangman_Game` 未复现；前者是 type-2 leak
    PoV（vulnerable 超时、patched 崩溃），后者 POV 以
    `short read in match` 退出 1，预期输出与当前移植不一致。
- **这不是 V0–V5 验收，也不是隔离 guest 结论**；只是“这两份构建在该
  POV 输入上确实不同”的探索性证据。

## 重放命令

```bash
python3 scripts/cgc_pov_replay.py \
  /usr/bin/qemu-x86_64-static \
  datasets/cgc-linux-build/challenges/Palindrome/Palindrome \
  datasets/cgc-linux-build/challenges/Palindrome/pov_1.pov 15
```

POV 与 challenge 的接线：

```text
pov stdin  <- challenge stdout
pov stdout -> challenge stdin
pov fd 3   <-> replay harness（type1/type2 协商、type2 submit）
```

## 解释与限制

- **移植差异**：`maths.S` 换成 libm 包装、`setjmp/longjmp` 占位、
  `mmap` 指针强转、UBSan 关闭；不是原 CGC 的 32 位 syscall ABI。
- **编译选项**：挑战 CMake 固定 `-O0`，且有源码/调试信息；不是 stripped
  生产二进制，也不是 BinPool 的 opt0–opt3。
- **模拟层**：qemu-user 是用户态模拟，不是带 uid 1003/seccomp/netns 的
  加固 guest；不能把这里的 `SIGSEGV` 直接当成平台级验收。
- **POV 语义**：CGC POV 不全是 crash PoV，也有 leak/logic PoV；
  `Board_Game` 的 exit 0/1 差异不能写成“漏洞已触发”。
- **结论强度**：2 个 POV 的 crash 差分只证明这两份构建在该输入上不同，
  不证明修复后的二进制在语义上等价于官方修复版。
