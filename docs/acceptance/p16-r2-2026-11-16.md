# P16-R2: plan-aware verifier progress (2026-11-16)

## What changed

- Exposed the existing `binary_pipeline.build_patch_plan` instead of
  generating authorization from a candidate diff.
- The benchmark verifier now replays a real layout plan (operations, cave,
  target scope, oracle metadata) built from original/candidate bytes and the
  recorded injection action.
- The cave ABI block is declared explicitly; the verifier still uses the
  Phase-8B layout/ABI/oracle gates.

## Verified progress on CWE-122

For one CWE-122 candidate with a real patch plan:

- layout-plan: **passed**
- action-replay: **passed**
- target-scope: **passed**
- runtime-oracle: **passed**
- independence: **passed**
- ABI: **failed** because the cave block is not yet resolvable through the
  unified ELF PT_LOAD mapping; it is reported as a symbol-backed target block
  with `no_ret`.

This is a strict verifier result, not an AI repair failure.  The remaining
P16-R2 work is exactly the ELF mapping/ABI cave derivation and real
authorization records.
