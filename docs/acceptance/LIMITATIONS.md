# Limitations of this delivery

This repository is an accepted MVP **with recorded limitations**. Do not cite it
as a fully independent, binary-level-proven, universally green product.

## 1. V4 is model-level

V4 is a typed symbolic claim over the target function. It is not binary-level
symbolic execution and not a whole-program proof. The result is `passed` at
`scope=model`; the binary-level claim is not made.

## 2. Coverage is one public fixture family

The delivery covers the public CWE-416 no-input repair path and the historical
CWE-121 MVP fixture. It is not evidence that arbitrary binaries, other
architectures, other compilers, stripped production binaries, or client binaries
work.

## 3. Test environment

The canonical full-suite record is a Linux run with Chrome CDP:

```text
714 passed / 2 Linux-only skipped / 0 failed
e2e 12 passed
```

Windows hosts are not the acceptance record. They skip Linux-only cases and
have POSIX-fixture differences; a Windows exploratory run is not a substitute
for the Linux record.

## 4. M4 verifier and Lead approver are the same operator

The verification row and approval row were signed by the same operator. This is
**role-separated, not independent two-person review**. A client requiring
genuinely independent approval is not satisfied by this delivery.

## 5. Review 9–12 original text is not recovered

The verdict is against a canonical reconstruction. It must not be described as
verbatim original review text. The source state is recorded in
`docs/development/reviews/review-9-12-m4-verdict-2026-11-07.json`.

## 6. V5 scope

V5 is build/replay reproducibility. It does not prove repaired behaviour.
`V5-replay.json` is a reproducibility result, and the four original logs are
tracked as evidence; they are not regenerated by this snapshot.

## 7. No tag or original-main merge

This repository is a curated delivery snapshot. It is not a release tag and is
not merged into the original repository's `main`.

## 8. Not a production product

This is a course/MVP deliverable, not a supported commercial vulnerability
remediation service. No client binaries, credentials, private keys or private
logs are included.

## 9. v5 "arbitrary binary" scope

v5 adds a universal binary-repair entry (`/binary`, CLI, `/api/binary/*`) and
explicit dispositions, but it is still not universal vulnerability repair:

- the deterministic repair matrix is ELF/PE/Mach-O on x86-64/arm64 plus 32-bit
  x86 (ELF32/PE32). Only copy sinks with a recoverable capacity are repaired
  (`strcpy`/`strcat`/`stpcpy` guards; constant-length `memcpy`/`memmove`/syscall
  clamps). Heap/global destinations, `sprintf` format expansion, UAF, integer
  and loop defects, and obfuscated/inlined copies are **analysis-only**;
- 32-bit x86 analysis models **push-materialised cdecl arguments**; argument
  setup such as `mov [esp+K], reg` is not analysed in v1 (fail-closed, keeps the
  i386 negative control honest); static-libc alias names not ending in a plain
  copy alias (for example `compiler_rt.memcpy.memcpyFast`) are also fail-closed;
- a candidate repairs **one function per run**; other vulnerable functions found
  in the image are reported as limitations and not patched, so every shipped
  action stays covered by the runtime case for that function;
- 32-bit Mach-O, fat Mach-O rewriting, arm32, riscv, mips, powerpc and
  big-endian containers are detected and analysed but never rewritten; fat
  Mach-O slices are reported individually (`slices[]`) but no fat binary is
  rebuilt;
- capacity is frame geometry (`frame_top - destination`) or an explicit
  `_chk`/immediate size, not DWARF object size; buffers that do not sit at the
  frame top can be over-estimated;
- PE and ELF runtime evidence is Unicorn instruction-level emulation of the
  repaired function, not a Windows/Linux kernel run. Mach-O native evidence
  exists only on macOS; elsewhere those candidates are `not_verified`;
- `static_only_patch` is explicit opt-in, unverified, and never reported as
  success. A failed gate drops the candidate (`rejected`); matrix-outside input
  returns `unsupported`/`analysis_only` and no bytes;
- report v4 dispositions are bounded claims: no whole-program proof, no
  arbitrary-vulnerability discovery, no claim that a repaired binary is safe for
  production use. See
  [`docs/acceptance/binary-universal-v5-2026-11-13.md`](binary-universal-v5-2026-11-13.md).
