# P5-P9: cross-binary repair, feedback, qualification and evidence

## Results

### P5 Native semantic feedback

Real DeepSeek flash, `hard-sprintf`, first attempt without a RepairSpec fails
the native security gate.  The observed failure is classified as
`candidate_crash`/retryable, fed back to the planner, and the second plan +
assembly is native **VERIFIED**.  Both rounds and candidates are preserved:
`artifacts/native-feedback-2026-11-15/`.

### P7 Cross-binary benchmark

`fixtures/repair-benchmark/cases.json`: 4 binaries, CWE-121/CWE-122/CWE-787
(plus the three original hard cases).  Final DeepSeek flash run:
**4/6 verified** - hard-multicall, hard-sprintf, hard-nonconst, and
`cwe122-heap-copy` (an unseen binary).  CWE121 remains `SECURITY_FAILED`;
CWE787 is `ASSEMBLY_REJECTED` (absolute branch-target labels).

Evidence: `artifacts/repair-benchmark-2026-11-15/`.

### P8 Model qualification

Same six cases, same planner/ABI/semantic-retry/native gate, two models:

| model | verified | result |

| deepseek-v4-pro | 2/6 | different cases verified, typed failures |

### P6 RepairSpec v2

Implemented nested v2 schema, validation, backward-compatible v1, and
`spec_from_plan`.  The current model evidence still uses v1 plans; v2 is tested
but not yet demonstrated as a production model output.  This distinction is
kept explicit.

### P9 Evidence

Added versioned repair-evidence bundle builder/checker
(`scripts/repair_evidence.py`, schema v2); bundles contain case statuses,
candidate files, source hashes and manifest.  Current artifacts use one run per
case; a 3-repeat stability experiment is not yet completed.

## Honest boundaries

- Benchmark is four binaries, not a broad population.
- Same-run model outcomes vary; qualification shows only 2/6 per model.
- CWE787 model output currently uses absolute branch labels and is rejected;
  this is a real toolchain/planning gap, not a false pass.
- Reference CWE416 UAF remains separate and is not AI evidence.
- No new architecture/static/PIE support.
