## Root cause

`Patcherex2.ModifyFunctionPatch` calls `AllocationManager.allocate()`, which
falls back to `_create_new_mapped_block()` (a new PT_LOAD) when no free space is
registered. The default `patch_function` registered none, so the recompiled
`badSink` body and its `"ERROR: …"` data each landed in a fresh segment
(`0x4058a8` R-E + `0x407000` R).

## The fix

In `routeb/probe_patcherex2.py::patch_function`:

1. find the unique R-X PT_LOAD and extend `p_filesz`/`p_memsz` to the next page
   boundary (`0x8e9 → 0x1000`, mapping the tail ending at `0x401fff`) — this is
   exactly `authorized_edits[1]`;
2. register that tail as RX free space via
   `p.allocation_manager.add_free_space(0x4018e9, 0x716, "RX")`;
3. let `ModifyFunctionPatch` place the recompiled body + data there.

Result: `same_program_header_count = true`, `extra_load_segment_count = 0`,
`program_header_order_changed = false`, `relocations_added = 0`.
