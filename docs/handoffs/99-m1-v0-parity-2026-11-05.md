# V0 binding parity, legacy all-not_run, and the result-bundle listing rule

- Date: 2026-11-05
- Owner: Member 1 (host backend)
- Base: `65aeb01` (contains `3b4e492` and `50be6f7`)
- Suite: `362 passed / 3 skipped / 1 failed` (host has no `readelf`/`objdump`)

## 1. V0 chooses the bound candidate, not the first file

`tools/route_bundle_ingest.py` now applies the hash-based selection **only to
V0**. The previous merge had widened it to every gate because both sides fixed
the same defect independently; that was broader than the contract and would
silently pick a candidate-looking file out of V1 if one ever appeared there.

The contract it matches is the Route B writer's: V0 passes only when the
original matches the job record and the declared candidate matches the edit
manifest. So the V0 evidence artifact must be the file whose bytes equal
`candidate_sha256` - which is exactly what `test_v0_picks_candidate_not_first_artifact`
asserts (decoy first in the list, candidate second).

## 2. A package without result-bundle.json stays all not_run

`_legacy_payload` only reads gate status from `result-bundle.json`. A legacy
INTERFACE-v1 package that has none gets `{}`, so every gate is `not_run`.

The real `P3B-package-v6` is exactly this case: its `handoff.json` notes claim
"V2 16/16 passed; V3 6/6 repaired_..." and it still produces

```
route_b = {identity: not_run, structure: not_run, interface: not_run,
           behaviour: not_run, symbolic: not_run, reproducibility: not_run}
verdict.reason = required_check_not_run
```

`test_legacy_without_result_bundle_is_all_not_run` now carries that same prose in
`notes` and asserts both the six `not_run` values and an empty evidence map, so a
future change cannot start parsing notes into gates without failing.

## 3. result-bundle.json must be listed twice

When a legacy package does ship `result-bundle.json`, it has to appear in both
`handoff.json#files` and `SHA256SUMS`.

- `handoff.json#files` was already enforced.
- `SHA256SUMS` was **not**: `_verify_sums` only checks the files it lists, it
  never requires the list to be complete. A gate-carrying file could therefore be
  unhashed and still ingested. Added `_sums_names()` and an explicit check.

Two tests cover the halves separately:

- `test_legacy_result_bundle_must_be_in_sums` - present on disk, absent from
  `handoff.json#files`;
- `test_legacy_result_bundle_in_handoff_but_not_sums_is_rejected` - declared in
  `handoff.json#files`, absent from `SHA256SUMS`.

## 5. Gate status is per-gate evidence only

No code path derives a gate from prose. `notes`, `bundle-record.md`, and handoff
prose are never read by the ingest adapter; only `gates[<gate>].status` plus that
gate's `artifacts` list can produce a non-`not_run` row.
