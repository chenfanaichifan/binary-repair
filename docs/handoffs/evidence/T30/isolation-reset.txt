## 2. Window identity — and the honest caveat

```
snapshot.current = "14"
snapshot name    = t15-t6-work
parent           = uid 11 (gate4-harness)
is baseline?     = NO
```

**This window did not start from the clean baseline.** Record 88 §3.1 calls for a
revert to the target snapshot before a run; that revert was not performed, because
uid 14 holds the T6.2 working state (job directories, the routea config, the
conformance build) that an earlier window produced and that has not yet been
archived elsewhere.

So this window is **working-snapshot clean, not baseline clean**. Stated plainly
because the difference matters: a reviewer comparing this build against a future
one should know which snapshot it came from. If a baseline-clean window is
required, revert to uid 11 and re-run `build/build.sh` plus `build/trigger.sh` —
both are deterministic and take under a minute, and the expected hashes are in
`build.json`.

## 3. Reset: NOT performed, and why

Record 88 §3.2 defines staging out as: copy artifacts out → power off cleanly →
verify `snapshot.current` and no `.lck` → revert to baseline.

Measured state at capture time:

```
VM running        yes (vmrun list: 1 running VM)
snapshot.current  14 (unchanged)
*.lck directories 12
```

| Step | Status |
|---|---|
| Copy artifacts out | **done** — `original.elf`, `readelf.txt`, sources, scripts are in this package and their hashes match the guest copies |
| Power off cleanly | **not done** — the VM is still running so the T6.2 state stays usable |
| Verify no `.lck` | **12 lck directories present**, consistent with a running VM |
| Revert to baseline | **not done** |

So the reset half of the window is **open**, not silently skipped. It closes when
the T6.2 working state is no longer needed: snapshot it if the disk state is the
deliverable (record 88 §3.2 step 3), otherwise revert to uid 11.
