## 4. V4 passed content gate

A bare `V4: passed` is not accepted. `app/domain/v4.py` defines a typed
`V4Evidence` model requiring:

```
typed gate/kind/scope/state/ran
candidate_sha256 + original_sha256
tool_versions
preconditions
memory_predicates
forbidden_ranges
hooks
exploration_accounting
solver_accounting
calibration
replay
claimed_scope
not_claimed
```

`validate_v4_evidence` also requires complete exploration/solver accounting, a
complete calibration, an identical replay, and hash equality with the manifest
candidate and the job original. Missing or inconsistent content is
**NOT VERIFIED**: `route_bundle_ingest` downgrades the gate to `unknown`, and
`persist_obligations` independently validates a passed V4 artifact and downgrades
it to `unknown` if the content is incomplete. A matching file hash alone cannot
make V4 pass.

`build_obligations` and therefore `evaluate_attempt(required=...)` force V2/V4
required; a caller-supplied `required={"V2": False, "V4": False}` cannot turn
them off.

`app/domain/v4.py#write_v4_evidence` is the write landing point: it validates
before writing and refuses incomplete content. A typed `v4-symbolic.json` now
has an explicit path:

```
bundle.json gates.V4 = passed, artifacts = ["v4-symbolic.json"]
  -> route_bundle_ingest validates the typed payload and registers it as V4 evidence
  -> persist_obligations re-reads the artifact and validates it again
  -> V4 obligation passed only if every field and every accounting count is present
```

The schema's `forbidden_ranges`, `memory_predicates`, `hooks`, `tool_versions`,
`preconditions`, `calibration`, `replay`, `claimed_scope` and `not_claimed` are
the documented V4 model obligations. The accounting fields match the harness
checklist in Lead records 125/126: `states_explored`, `states_pruned`,
`resource_pruned`, `max_depth`, `complete`; and per run `queries`, `sat`,
`unsat`, `unknown`, `eval`, `timeouts`, `steps`, `max_steps`, `complete`.
`steps >= max_steps` is rejected as capped/not proven, not passed.

Hardening added:

- `calibration` requires `known_good`, `known_bad` and `known_bad_rejected` all
  true, `cases >= 2`, `known_good -> passed >= 1`, and
  `known_bad_rejected -> failed >= 1`;
- `complete=True` forces `unexplored == []`, `unknown == 0`, `timeouts == 0`;
- `claimed_scope` is the literal `"model"`, not free text;
- `not_claimed` must explicitly include a `binary-level` exclusion.

These are fail-closed constraints. They do not make the existing bundle/persist
path a pass: 124's V4 remains `not_run`.

`from_v4_harness` / `tools/v4_harness_to_evidence.py` convert an actual M3
harness output into this same schema; they do not define a second writer and do
not ingest the result. No producer is wired into Route B, so record 124's V4
stays `not_run`; the schema/writer do not manufacture a pass.

This gate is dormant for record 124 because its V4 is `not_run`, not passed.
