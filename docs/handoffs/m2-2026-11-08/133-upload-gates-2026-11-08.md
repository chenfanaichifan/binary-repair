## 2. 非 HTTP 模式隐藏上传按钮

### 实现

```js
// app/static/js/agent.js:20-28
var UPLOAD_AVAILABLE =
  window.location.protocol === "http:" || window.location.protocol === "https:";
```

```js
// app/static/js/agent.js:1568-1575
var uploadButton = $("agent-deliverable-upload");
var uploadInput = $("agent-deliverable-input");
if (!UPLOAD_AVAILABLE) {
  if (uploadButton) uploadButton.hidden = true;
  if (uploadInput) uploadInput.hidden = true;
}
```

### 行为

| 打开方式 | 上传控件 | 原因 |
|---|---|---|
| `http://` | 显示 | 后端可达 |
| `https://` | 显示 | 后端可达 |
| `file://` | 隐藏 | 没有同源 API，点击只会得到网络错误 |

隐藏的是输入框和按钮两个元素，避免留下一个「能点但必然失败」的控件。
状态文案元素保留，避免布局跳动。

## 3. 64 MiB 前端提示

### 实现

```js
// app/static/js/agent.js:26-28
/* Mirrors DELIVERABLE_MAX_BYTES in app/controller_api.py ... */
var DELIVERABLE_MAX_BYTES = 64 * 1024 * 1024;
```

```js
// app/static/js/agent.js:1540-1543
var file = input.files[0];
if (file.size > DELIVERABLE_MAX_BYTES) {
  setText("agent-deliverable-status", "文件超过 64 MiB 上限，已取消上传");
  return;
}
```

### 设计取舍

- 常量与后端 `controller_api.py:1435` 的 `DELIVERABLE_MAX_BYTES = 64 * 1024 * 1024` 一致
- 超限时**不发请求**，直接给中文提示，省掉一次必然 413 的上传
- 后端 413 仍然保留，作为绕过前端的兜底（双保险，不是替代）

## 5. 为什么是源码级断言

本机没有 node，跑不了 JS 单测。项目既有 `test_agent_console.py` 就是读
`AGENT_TEMPLATE` / `AGENT_JS` 文本做断言，这里沿用同一风格。

真实浏览器行为由 `tests/e2e`（CDP）覆盖；本次没有跑 e2e，因为它需要
启动服务加 Chrome，而这两项改动不涉及网络时序，静态断言足够定位回归。
