## 1. The edit is the contract's first authorised option

`contract.json#authorized_edits[0]` allows "drop the `free()` and accept the
leak". The second option — moving the read ahead of `free()` — needs inserted
instructions, so it changes more bytes for the same behaviour. This takes the
first:

```
vaddr 0x401305   file offset 0x1305
e8 e6 fd ff ff   call 4010f0 <free@plt>     ->  90 90 90 90 90
```

Everything else is copied through: entry `0x4011b0`, 37 sections, 14
relocations, program headers and section layout identical (`audit.json` carries
both sides). The 100-byte block therefore stays allocated and `printLine()`
reads the text it wrote instead of tcache residue. The price is a leak at exit;
that is inside the authorised edit, and it is why the fix is one instruction
rather than a relocation.

No C replacement, no code cave, no added byte: `edit_method.replacement_c` and
`.code_cave` are both `false`, and `replacement_c_sha256` is `null` rather than
a hash of something unused.

## 2. V3, measured through the v3 schema

`routeb/run_manifest_repaired.py --contract <fixture>/contract.json` resolves the
mode with `contract_mode.load_contract` → `SecurityContract.from_dict`, so
`none` comes from the schema and not from a JSON read:

```
input_mode: none   invalid: not_applicable   valid: 1/1
passed: 1   total: 1   repaired_pass: true
```

The control matters more than the number. The same runner, the same manifest,
pointed at the **unrepaired** original:

```
valid: 0/1   passed: 0   total: 1   repaired_pass: false   (runner exit 1)
```

One case flipping between two binaries is what the evidence is worth. `1/1`
alone would only say the runner ran.

On determinism, precisely:

- the repaired binary prints 100 bytes (99 `A`, then `\n`) with ASLR on or off,
  because it no longer reads allocator metadata;
- the original prints residue through `printLine()`, so the length depends on
  where the heap landed. ASLR off gives the frozen `05040a` in `defect.json`;
  the control ran with ASLR on and recorded `4ba2020a`. Both are residue,
  neither is the 100-byte string. This is why the fixture freezes the
  observation under `setarch -R` and why the repaired expectation does not need
  it.

`invalid: not_applicable` is not `0/0`, not `0/2`, not `skipped` and not a
missing field: there is no `invalid.json` in the fixture, and the runner refuses
one if it appears.

## 4. What this does not become

**Not a verdict.** `contract.json#required_obligations` still lists `symbolic`.
An attempt assembled from this bundle is `REQUIRED_CHECK_NOT_RUN` →
`inconclusive`, not `pass`. Writing `repaired_pass: true` in a manifest is not a
gate decision, and this record does not make one.

**V4 stays `not_run`.** No symbolic or bounded-model engine ran; `claimed_scope`
is `null` and the file lists what is not claimed. A replay is `replay` scope.
Calling the five-byte patch a binary-level proof, or a model-level one, would be
false in both directions.

**V2 stays `not_run` in the score.** `v2-interface.json` records that the target
symbol row, the dynamic symbol table, `NEEDED` and the entry point are unchanged
between the two binaries. It is marked `"scored": false` because Route B has no
interface check; a symbol diff is an observation, not a gate.

**T8.3 stays blocked.** One repair of one sample says nothing about a defect
class. No second sample is described, and none is implied by the tests passing.

## 5. Checking it without trusting this record

```sh
cd docs/handoffs/evidence/cwe416-candidate-2026-11-05
sha256sum -c SHA256SUMS                       # 30/30
sha256sum SHA256SUMS                          # f9dc0be5…8eeb

```

`SHA256SUMS` holds every file except itself and `bundle-sha256.txt`;
`bundle-sha256.txt` is `sha256(SHA256SUMS)`, which is why the package can be
checked from outside without the listing hashing itself.

One trap, recorded because it cost a run: the fixture ships `original.elf` as
mode `100644`. `cp` and `tar` keep that, and an un-executable copy fails as
`[Errno 13] Permission denied` inside the runner — which reads like a missing
file. `run_all.sh` does `chmod 755` after each copy.
