## Migration number collision

M5 ships `005_assistant_messages.sql`; this branch had already used version 5 for
`005_obligation_scope.sql`. `_migration_files()` sorts by filename and
`apply_migrations` skips any version `<= current`, so two files numbered 5 would
have silently dropped the second one - and which one lost depended on filename
order. Renamed this branch's file to `006_obligation_scope.sql`; M5 keeps 005.
`tests/test_db_v2.py` now expects `[1, 2, 3, 4, 5, 6]` and asserts
`obligations.scope` exists.

## V3 detail (item 3)

The writer already refused to treat `manifest-compare.json` as repair credit, but
the database lost that fact: `obligations` only ever stored one `behaviour` row,
so "unchanged round trip" and "repaired and verified" were indistinguishable in
SQL and in `/api/jobs/{id}/obligations`.

`persist_obligations` now also writes the kind row the writer computed
(`details["V3_kind"]`):

- `round_trip` - non-required, replay scope, result mirrors the gate (normally
  `not_run`); the `behaviour` row stays `not_run`, so no credit.
- `repaired_behaviour` - non-required, replay scope, result mirrors the gate and
  carries the V3 evidence artifact id.

`required` stays false on both so the verdict model is untouched: V3 credit is
still decided by the `behaviour` gate row, which only reaches `passed` when the
repaired runtime actually passed.

`tests/integration/test_v3_kind_rows.py` asserts both shapes directly in the
database.
