# 92 — T8.2 LLM planner handoff to M2

**Date:** 2026-11-05
**Decision:** T8.2 owner is M2. M5 keeps T8.1 (schema, deterministic planner,
migration, persistence), T6.6 provider integration, and T6.1 ingest.

## Ownership split

M5 keeps and must not be edited by M2:

```text
app/domain/assistant.py       # AssistantPlan schema + deterministic_plan
app/db/migrations/004_assistant.sql
app/services/assistant.py     # stable seam: generate_plan/get_plan/save_plan
tests/integration/test_assistant_plan.py  # scripted + seam tests
```

M2 owns:

```text
app/services/assistant_llm.py             # prompt, provider call, usage point
tests/integration/test_assistant_llm.py   # fake-transport/usage tests
```

M5's `model_calls` service remains available; M2 calls
`model_calls.record_call` from `assistant_llm.py`.

## Stable seam

```python
assistant.generate_plan(
    job_id,
    data_dir=...,
    mode="llm",
    client=<optional fake/real client>,
    planner=<optional callable>,
)
```

`planner` is called exactly as:

```python
planner(job_id=job.id, data_dir=data_dir, client=client)
```

and must return the dict from `assistant.save_plan(...)`. If `planner` is None,
M5 lazily imports `app.services.assistant_llm.generate_llm_plan`. Any planner
exception is converted by M5 into a deterministic fallback plan with
`fallback_reason`; it never writes a verdict.

## Handoff rules

- M2 edits `assistant_llm.py` and `test_assistant_llm.py` only.
- Do not edit `app/services/assistant.py` for T8.2; use the seam.
- Do not move usage recording back into `assistant.py`.
- The fake-transport tests and usage assertion live in
  `tests/integration/test_assistant_llm.py`.
- `AssistantPlan` remains display-only; no approve/start/verdict.
