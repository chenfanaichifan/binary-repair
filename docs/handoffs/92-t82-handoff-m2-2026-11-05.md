## Stable seam

```python
assistant.generate_plan(
    job_id,
    data_dir=...,
    mode="llm",
    client=<optional fake/real client>,
    planner=<optional callable>,
)
```

`planner` is called exactly as:

```python
planner(job_id=job.id, data_dir=data_dir, client=client)
```

and must return the dict from `assistant.save_plan(...)`. If `planner` is None,
M5 lazily imports `app.services.assistant_llm.generate_llm_plan`. Any planner
exception is converted by M5 into a deterministic fallback plan with
`fallback_reason`; it never writes a verdict.

## Schema status

`AssistantPlan` now has steps 1..6, `kind in {input, action, review}`,
review as the final step, and questions with five fields
(`id`, `prompt`, `options`, `required`, `allow_free_text`). The exact
`assistant-plan-v1.md` at c3bb709 was not present in this checkout; if its
field names differ, M2 owns the contract reconciliation and should tell M5
before changing the schema.

Deterministic defaults are ASCII-only, pure (no env/DB), and validate through
Pydantic; invalid shape raises rather than returning a partial plan.

## Exact M2 contract implemented (2026-11-05)

The plan wire shape now matches M2's `assistant-plan-v1` example:

```text
plan_id, mode deterministic|llm, fallback, fallback_reason, model, tokens
steps 1..6: id, kind upload|question|review, title, prompt, questions
questions: key, label, input text|textarea, required, ascii, default
review is the last step
```

Deterministic planner entry point:

```python
deterministic_plan(description: str, context: dict | None = None) -> AssistantPlan
plan = deterministic_plan  # compatibility alias
```

It is pure (no env/DB/network), ASCII-only defaults, and Pydantic rejects
partial/invalid plans.
