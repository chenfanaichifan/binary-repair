## 1. Defects found while making the re-run work (all fixed and committed)

1. **Guest/host contract-hash rule split.** The 2026-11-07 worker and collector
   hashed the contract with a plain JSON-dumps rule (`2dea9b4c…`), while the
   host trust boundary recomputes `app.domain.contracts.contract_sha256`
   (`c1684f15…`). Fixed in `workers/route_a/worker.py` and
   `workers/route_a/result_bundle.py`; both fail closed if the product rule is
   unavailable. Tests: `tests/test_route_a_guest_worker.py` (4 passed).
2. **Executor V3 collection path.** `run_candidate.py` wrote
   `out/manifest-repaired.json` while the collector read
   `evidence/v3/manifest-repaired.json`, so a guest run always recorded V3 as
   `not_run`. Fixed in `workers/executor/run_job.py`.
3. **V0 bundle-contract check used the wrong canonicalisation.** The P0
   validator compared the bundle contract with a plain dumps digest instead of
   the product rule, so a real bundle (whose contract file is pretty-printed)
   could never pass V0 even when the reviewed contract was the same body.
   Fixed in `app/domain/route_a_evidence.py`; regression test added
   (`tests/test_route_a_evidence.py`, 22 validator/boundary tests pass).
4. **Legacy contract serialization is incompatible with the P0 byte check.**
   The 2026-11-07 kit's `contract.json` is the pretty fixture file
   (`sha256 8a2b408c…`); the P0 boundary requires the bundle contract file to be
   byte-identical to the reviewed contract file, which the controller stores in
   canonical form (`sha256 c1684f15…`). The re-run package therefore uses the
   canonical serialization of the **same contract body**; the canonical hash is
   unchanged. A production flow that keeps pretty contract files in the bundle
   would need a decision, because the two serializations cannot both satisfy
   V0's byte binding and the old V4 marker's file-hash binding.
