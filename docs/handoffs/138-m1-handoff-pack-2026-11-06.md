
442 + 7 = 449, and 9 - 7 = 2, which is exactly the Lead's `449 / 2 / 0`. So the
seven that must start passing are the two `test_fixture_v3_manifest` cases and the
five `test_v3_no_input_e2e.py:121` cases.

**(b) 7 e2e tests error here** with `ModuleNotFoundError: No module named 'websockets'`.
The venv has `httpx` but not `websockets`, and no `playwright`. Installing
`websockets` may convert those errors, but whether they pass or skip still depends
on the e2e guards; the Lead's full run has 9 skipped and 449 passed, meaning those
seven are skipped there rather than passing.

**(c) live-bridge has one real local failure**, independent of the above:
`tests/test_evidence_endpoint.py::test_evidence_serves_persisted_rows_verbatim`
fails because the endpoint returns rows in a different order than the fixture
inserted them (stored[0] is `identity`, expected[0] is `behaviour`). 505 + 1 + 7
= 513, which matches the Lead's 513 once the local failure passes and the seven
