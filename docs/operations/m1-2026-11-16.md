## 1. Objective

The CWE-121 case (`cwe121-unchecked-strcpy`) already produced a valid repair
plan and injected assembly, but the candidate returned silently on oversized
input. The behavioral contract requires a controlled failure instead:

- exit code `1`;
- empty stdout;
- stderr exactly `ERROR: input exceeds destination capacity\n`;
- unchanged behavior for valid inputs.

The assembly path was leaf-only, so it could not express a process exit or an
exact stderr write. This increment adds the missing plan vocabulary and a
minimal, fail-closed call surface without relaxing any gate.

## 3. Failure behavior schema

```json
{"exit_code": 1, "stdout": null,
 "stderr": "ERROR: input exceeds destination capacity\n",
 "stdout_hex": null}
```

Validation is fail-closed:

- unknown keys -> `failure_behavior_unexpected_fields:<keys>`;
- `exit_code` must be an integer in 0..255 (`True`/`False` rejected);
- `stdout`/`stderr`/`stdout_hex` must be strings when present;
- `stdout` and `stdout_hex` are mutually exclusive;
- `stdout_hex` must be valid hex;
- an all-null object -> `failure_behavior_empty`;
- v1 plans without the optional field stay valid (`null` contract).

The benchmark cross-checks a plan-stated field against the PoC candidate
expectation and reports `failure_behavior_mismatch:<field>` instead of
silently accepting a contradiction.

## 4. Controlled calls (minimal surface, fail-closed)

Two mechanisms exist, both narrower than an arbitrary call:

1. Real ELF PLT imports. Only names on a failure-relevant list (`exit`,
   `_exit`, `fputs`, `fwrite`, `fprintf`, `write`, `puts`, `printf`, ...)
   are surfaced, and only when the target ELF already has an executable PLT
   entry for that exact name. If the import is absent it is not exposed.
2. Fixed x86-64 Linux syscall templates. The model may invoke exactly
   `call br_write_stderr`, `call br_write_stdout` and `call br_exit_group`.
   The host expands them into canonical instruction sequences:
   - `br_write_stderr`/`br_write_stdout`: `write(2|1, stack buffer, len)`
     with the exact contract bytes embedded by the host;
   - `br_exit_group`: `_exit(exit_code)` with the contract exit code.

Fail-closed rules:

- templates exist only for ELF x86-64 and only for fields the plan actually
  declares; no contract means no template;
- the model may not write `syscall` itself (text preflight rejects it);
- after assembly every syscall is re-validated byte-pattern-exactly against
  the contract bounds (write fd in {1,2}, write length equal to the contract
  payload, exit code equal to the contract code); any other syscall fails;
- an unknown template name or a hand-written forbidden call is rejected and
  never rewritten;
- the injected block still passes the existing ABI check and target-scope
  redirect.

## 7. P0-2 - CWE-134 field-level plan diagnostics and minimal fix

The historical CWE-134 run failed before assembly with the bare typed error
`affected_address_out_of_scope`. Root cause: the v2 plan put a *mapping* of
named addresses in `program_context.addresses` (function/call/callee/ret
VAs), the validator converts mapping values to a list and requires every
address inside the resolved target function scope, and the callee `printf`
PLT address (0x401050) lies outside `cwe134_bad` [0x401156, 0x40117f). The
planner packet did not publish that scope, so the planner could not avoid
the violation.

Fixes (still fail-closed, no gate change):

- `app/services/repair_spec.py`: new `diagnose_plan_error()` turns the typed
  error into `{schema_version, reason_code, field, expected, detail}`. For
  example the CWE-134 failure now yields
  `field=program_context.addresses` and
  `expected="every address inside target_scope [0x401156, 0x40117f)"`.
- `scripts/run_hard_benchmark.py`: the planner packet now publishes the
  half-open `target_scope` plus a scope rule; every planner attempt records
  its diagnostic, results carry `plan_invalid`, and run summaries/manifests
  record `plan_invalid_reason_codes`, `plan_invalid_field` and the typed
  diagnostic. The same scripted-historical plan remains rejected (fail
  closed); only a corrected in-scope plan becomes valid.
- Minimal CWE-134 strategy: the existing `format_string` strategy plus a
  scripted minimum fix (`printf("%s", src)` built with a fixed `%s` literal
  on the stack and the already-imported `printf` PLT target) is injected
  through the real pipeline. The native PoC runner passes: `%s` input no
  longer crashes (candidate exit 0, stdout `%s`), regression input `hi`
  still prints `hi`.

Evidence: `artifacts/m1-2026-11-16/cwe134-plan-diagnostics-evidence.json`
(plan diagnostics + PoC gate). Deterministic stand-in, no live model.

## 9. Limitations and next steps

- The fixed write templates embed the contract bytes as immediates; payloads
  are capped at 512 bytes.
- Syscall templates are x86-64 Linux only; other architectures keep the
  import-only path and therefore fail closed for exit/stderr contracts.
- The stand-in assembly is a harness reference, not a model answer; the
  next capability step is to run the same path with a live planner/assembly
  model (requires an explicit cost decision by the Lead).
- CWE-134 plan diagnostics are recorded, and the minimal `format_string` fix
  passes the native gate with a scripted stand-in; a live-model run remains
  not_run (no provider key use authorised).
