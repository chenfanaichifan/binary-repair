# Two AI direct-binary repair paths — scripted acceptance evidence

Generated by `scripts/capture_ai_binary_repair.py` (2026-11-13).  The model is a
deterministic **scripted** client: no network/provider is used.

- `ai_plan`: the model only chooses `{sink_index, strategy}` from a bounded
  metadata packet; the deterministic writer emits the bytes.
- `ai_bytes`: the model emits raw machine-code guard bytes (`inject.code_hex`)
  or same-length in-place edits (`edits[]`); a strict static validator constrains
  the bytes and the existing writer applies them.
- Both paths end in the same deterministic reparse/runtime/gate; neither
  produces assembly text and reassembles it, nor decompiles to C and recompiles.

Fixtures: PE x86-64 guard, ELF arm64 guard, ELF i386 memcpy immediate; all six
positive records are `verified_patch`.  `negative-bytes-noop-guard.json` shows a
structurally valid but semantically empty guard (`c3` = `ret`) rejected by the
deterministic runtime gate (`verified=false`, `rejected`).

Candidate binaries are not stored; reproduce with the command above.
