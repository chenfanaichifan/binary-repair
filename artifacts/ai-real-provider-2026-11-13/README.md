# Real-provider AI repair experiment (2026-11-13)

Generated by `scripts/run_ai_provider_experiment.py` with the operator's
configured provider (no key or raw prompt/response is stored).

Six tasks: three `asm_roundtrip` (ELF i386/x86_64/arm64 guard) and three
`binary_direct` (PE x86-64/arm64 guard, ELF i386 memcpy immediate).  The no-AI
baseline is the deterministic v5 engine on the same fixture.

Result:

| metric | value |
|---|---|
| AI verified | **3 / 6** |
| deterministic baseline verified | **6 / 6** |
| coverage increment | **0** |

Honest failures:
- `asm_roundtrip` ELF x86-64: model assembly passed static validation but the
  deterministic runtime/gate rejected the candidate (semantic/runtime failure).
- `binary_direct` PE x86-64: model emitted an injected block containing a
  forbidden `call`; validator rejected before writeback.
- `binary_direct` PE arm64: model block ended in `mov` (fall-through); validator
  rejected before writeback.

This is an exploratory quality measurement, not a CI gate.  All benchmark
fixtures are already repairable deterministically, so **coverage increment on
this set is expected to be zero**; no real-LLM increment is demonstrated.
A gate-blind/PoC benchmark on cases the deterministic baseline cannot repair is
still required to answer the core AI-increment question.
