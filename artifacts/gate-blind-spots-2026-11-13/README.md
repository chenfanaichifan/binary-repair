# Gate blind-spot experiment (2026-11-13)

Generated by `scripts/gate_blind_spot_experiment.py`; candidates are produced
through the real AI protocols with scripted stand-ins, so no provider/network is
used.  The experiment asks: does the deterministic gate reject structurally
valid but semantically deviant candidates?

| case | gate outcome |
|---|---|
| assembly no-op (`ret`) | caught: runtime/gate rejected |
| assembly wrong destination | caught: runtime/gate rejected |
| assembly copy without NUL terminator | caught after destination-fill hardening |
| direct extra unrelated executable edit | caught after restricting edits to the selected length immediate |
| assembly correct copy **without original `puts` side effect** | **blind spot: memory-safe candidate verified; stdout side effect not compared by the runtime oracle** |

Summary: 4/5 semantically deviant candidates caught; **1 known residual blind
spot** (I/O side effects are outside the current runtime contract).  The
experiment records the residual instead of hiding it.  Closing it requires a
stdout/side-effect differential or a richer behavior contract; this is separate
from the memory-safety gate and is documented as future work.
