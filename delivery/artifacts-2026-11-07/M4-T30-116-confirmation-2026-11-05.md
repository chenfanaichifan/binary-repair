## 2. T30 — upstream source verification

### 2.1 Four-tuple and byte identity

| Field | Value |
|---|---|
| repo | `dsp-testing/samate-c-cpp` |
| commit | `01e353daa3d28a4ce2ae68904cbcde5e03e3519d` |
| path | `C/testcases/CWE416_Use_After_Free/CWE416_Use_After_Free__malloc_free_char_01.c` |
| SHA-256 | `fa84a6bb9df36a8a1ab4d33a7064746d9037247f7599d3cd39659478d4b7f42e` |
| size | 3,198 bytes |

Measured on the delivered bytes:

- `T30/original.c` SHA-256 = `fa84a6bb…7f42e` — identical to
  `cwe416-source-pin.zip`'s pinned copy and to `build.json#fixture.source_of_truth.sha256`;
- `diff T30/original.c pin/CWE416_…_01.c` → **IDENTICAL**.

So the case source shipped in T30 is the upstream file, not a rewritten one.

### 2.2 `INCLUDEMAIN` — present, and deliberately not defined

| Check | Observed |
|---|---|
| `#ifdef INCLUDEMAIN` in `original.c` | line **91** |
| `int main(int argc, char * argv[])` | line **93**, inside that guard (guard closes at line 110) |
| `-DINCLUDEMAIN` in `build.sh` | **absent** |
| any `-D` macro in `build.sh` / `build.json` | **none** |
| `main` symbols in `original.elf` | **exactly one**, at `0x401296`, size **20** |

The single `main` is the harness entry point, not the upstream one:
disassembly shows it calls `CWE416_Use_After_Free__malloc_free_char_01_bad`
once and returns 0. The upstream `main` would instead call `srand`, `printLine`,
`_good()` and `_bad()` and could not be 20 bytes.

**Determination:** the upstream `main` is excluded by the preprocessor guard; the
harness supplies the entry point. Nothing rewrote the guard or the source.

Record 118 §1 states the same answer independently (`original.c:91/93/110`,
`harness.c:21/23`, no `-DINCLUDEMAIN`). M4's measurement agrees with it; the
agreement is corroboration, not the basis of this finding.

### 2.3 Build command

`build.sh` compiles exactly:

```text
harness.c
original.c               (unmodified case source)
<juliet>/C/testcasesupport/io.c
```

and `build.json#build.link_units` matches. There is no `sed`, no patch, no
`-D` macro, and no substituted source file. `original.c` is compiled as delivered.

### 2.4 The built binary really contains the upstream body

Symbol table of `original.elf`:

| Symbol | Address | Size |
|---|---|---|
| `main` | `0x401296` | 20 |
| `CWE416_…_bad` | `0x4012aa` | 111 |
| `CWE416_…_good` | `0x4013df` | 31 (present, unused by the harness) |
| `printLine` | `0x4013fe` | 38 |

`_bad` disassembly matches `original.c:29–36` statement for statement:

| Upstream source | Observed instruction | Import |
|---|---|---|
| `malloc(100*sizeof(char))` | `movl $100, %edi` → `callq 0x401150` | `malloc` |
| `if (data == NULL) {exit(-1);}` | `cmpq $0` / `jne` → `movl $-1, %edi` → `callq 0x401180` | `exit` |
| `memset(data, 'A', 100-1)` | `movl $99, %edx`; `movl $65, %esi` → `callq 0x401130` | `memset` |
| `data[100-1] = '\0'` | `addq $99` → `movb $0, (%rax)` | — |
| `free(data)` | `callq 0x4010f0` | `free` |
| `printLine(data)` | `callq 0x4013fe` | local |

PLT→GOT mapping confirmed against the relocation table:
`0x4010f0 → 0x404000 = free`, `0x401130 → 0x404020 = memset`,
`0x401150 → 0x404030 = malloc`, `0x401180 → 0x404048 = exit`.

### 2.5 Determination: not a synthetic replacement

The vulnerable translation unit is **upstream bytes, compiled unmodified**. The
only evaluator-side addition is `harness.c`, a 20-byte `main` that calls the
upstream `_bad()`, and it is explicitly labelled "evaluator-side build
infrastructure … NOT part of the repair input" in its own header.

Precise classification: **upstream case source + harness-supplied entry point**.

Two caveats stated rather than hidden:

1. It is **not** "upstream's own `main`". The upstream `main` is intentionally not
   compiled (`INCLUDEMAIN` undefined). This is a documented harness deviation,
   not a source substitution.
2. `_good()` is still compiled in (no `-DOMITGOOD`), though the harness never
   calls it. Harmless, but it means the binary is not bad-only by construction.
